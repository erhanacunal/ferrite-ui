# Compiler and .fl notes

Language pitfalls and compiler changes (the language itself: docs/ferrite-lang.md).

## `.fl` pitfalls
- A generated on_click dispatcher calls **every** handler registered for a widget (ui.fl's back button uses `ui_back_custom` for apps that override it); arrays can't be passed to functions; a global may not share a name with any function's param/local (`color`, `radius` in ui.fl).
- Images: `MAX_IMAGES` 64 with `pool_large`/`host` (8 otherwise); `Image::draw` takes signed coords and clips to the scissor/screen (a picture sliding in from off-screen).

## Compiler: untyped float locals
- An unannotated `var` (type `any`) initialized from a float expression is now typed float (`CodeGen._stored_type`), locals and globals. Before, `var c = itof(n); var d = sin(a); c + d` compiled to the **int** add (any + any → int path, and `BIN_V` with superops). Checked: every other example compiles to identical bytecode.

## Compiler: classes (2026-11-16)
- `class Name { var field...; fn method() {...} }` (docs/ferrite-lang.md "Classes"). Compiler-only, no opcodes or caps: an instance is a `T_ARRAY` pool block, one word per field. The parser lowers a class (`_lower_class`) into ordinary `FnDef`s: methods become `Name.method(self: Name, ...)`, the constructor is a function named `Name` (init's params) that runs `__new("Name")` (alloc + field initializers + array fields, `CodeGen._gen_new`), calls `Name.init` and returns `self`. A class name is a type string in `var_types`/`param_types`; `CodeGen.classes` holds the layouts (`_register_classes`, after functions and globals are typed). `obj.field` on a class-typed variable → array ops with a constant index (`_gen_field_*`), else the widget property path. `obj.m(...)` parses to `CallExpr('.m', [obj, ...])`, resolved by the receiver's type (`_method_name`). `free(obj)` → `drop()`, array fields, instance.
- Chains (same day): after `name.` the parser loops over `.field`, `.method(..)` and `[index]`. `name.field` stays a `DotExpr` (widget or class); deeper links are `FieldExpr(base, field)` / `ElemExpr(base, index)`, method calls `CallExpr('.m', [receiver, ..])` with any receiver expression (`_method_name` uses its inferred type). Stores to them are `LStore(target, op, value)`; `++`/`--` on fields and array elements (`IndexExpr` too) are `IncDecLExpr`. `CodeGen._lvalue(target)` gives base/index/load emitters for all store targets; `_gen_lstore`, `_gen_lincdec` use it. No OVER/DUP2 opcode, so `+=`/`++` re-evaluate the target: `_lv_pure` rejects targets with calls or `++`. The lambda capture walkers know the new nodes.
- Inheritance (same day, option "A": compiler-only, no vtable): `class C : P`. `_register_classes` walks the trees in preorder: a class in a tree (has a parent or children; `in_tree`) gets a class id, its instances a hidden word 0 holding it (`__new` stores it), and `[id, last]` is its subtree's id range. Fields: the parent's, then its own (`index` is absolute, so field access through a base type just works). Methods: `_resolve_method` walks up; `_resolve_call` returns the declared class's implementation plus the overriders in the receiver's subtree. With overriders, `_gen_method_call` pushes receiver + args, reloads the receiver (`_lv_pure`) or keeps it in a hidden local `__recvN` (counted into FRAME by `_count_recv_temps`, only when a hierarchy exists), reads word 0 and tests ranges deepest first (`_emit_class_test`) before one static CALL each. `super.m()` → static call of the parent's resolution with `self`. `is`/`as` (`IsExpr`/`AsExpr`) are contextual (clock.fl has `var as`). `free()` on a tree class calls the synthesized `C.__free` virtually (`__freebody`: drop, owned arrays, instance). Override = same param/return types (checked). The parser lowers a subclass without `init` to a constructor running the nearest base `init`.
- Why not a vtable in the image: the VM has no call-by-function-id opcode (ids are only for callbacks, `find_func` is linear), and the GD32 object header has no spare bits for a class id. Next step if dispatch chains show up in profiles: a pool-array vtable + a `CALL_ID` opcode (cap-gated), same language.
- Limits: manual lifetime. Adding classes, chains and inheritance left every example's bytecode identical.
- Test: ferrite-ui-xl `ferrite-core/testdata/classes/classes.fl` (`gen.py`) → `runtime::class_tests`.

## Compiler: widget constructors (2026-11-16)
- `Button(text: "OK", children: [...], parent: w)` (docs/ferrite-lang.md "Widget constructors"). Compiler-only, a parser lowering: `widget Name[: Base](prop: value, ...);` at top level (`widget` is contextual there, a type name elsewhere; `Parser._widget_decl_at`) stores default properties in `Parser.widgets`. `Name(` for a declared name parses to a `WidgetExpr`, which `_block` expands (`_lower_widgets`/`_lower_widget`) into `var x = alloc()` / `x = alloc()`, `parent(p)` and `x.prop = v` statements spliced into the block. So the output equals the hand-written form (widget page, `W_ALLTAR` target tracking), and lowering into plain statements is why it only works in statement positions (`var`/assign/expression statement/`return`/`children`); anywhere else `_gen_expr` and `_infer_type` raise a clear error. Unnamed widgets use hidden locals `__w<depth>` (one per nesting depth and function, declared at first use; `_wscopes`).
- Callbacks: on_click etc. go through the generated dispatcher, which is built from the source text by regexes. `on_click: @h` in a constructor is found from the AST instead: `_ctor_callbacks` parses once (only if the source has `on_*:`) and passes `Parser.widget_callbacks` to `_generate_dispatchers(source, extra)`; the widget variable must be a global.
- `x = f()` with `f -> widget` now makes `x` a widget variable (`_gen_assign`), so `target(x)` accepts it (needed for `extra = card("y")` children).
- Adding the declarations to lib/core.fl and lib/flex.fl left every example's bytecode identical.
- Test: ferrite-ui-xl `ferrite-core/testdata/widgets/ctor.fl` (`gen.py`) → `runtime::widget_ctor_tests`.

## Compiler: error lines through #include (2026-11-16)
- `preprocess_map` returns the expanded source plus each output line's origin (absolute path, line); an included file replaces its `#include` line, and what follows the directive on that line stays on a line of its own. `preprocess` wraps it. `compile`/`build_image` call `CompileError.locate(line_map, filename)`, which sets `e.file` (None = the main file, else the path relative to its directory) and `e.line` in that file; lines past the map are the generated callback dispatchers. Before, every error after an include reported a line of the expanded source (line 3 of main.fl came out as "line 236" after `core.fl` + `flex.fl`).
- Message forms: `line N: msg` (main file), `sub/x.fl line N: msg` (included). `ferrite_build.compile_program` re-raises as `path:N: msg`, with the error's own file. A missing include is reported at the `#include` line of the file that asked for it.
- Bytecode unchanged for every example.

## Compiler: unused-function elimination (2026-11-18)
- `build_image(strip_unused=True)` (default): compile once with every function (so all code is still type-checked and errors are reported), then, if some functions of `#include`d files are unreachable, compile again without them. Reachability: roots = functions whose name is in `SYSTEM_CALLBACK_KINDS` (what the VM calls, incl. the generated dispatchers); edges recorded while emitting (`CodeGen._note_ref` from `_emit_call` and `_resolve_func_id`, i.e. every CALL, `@name`, lambda, method dispatch, `free` → `__free`/`drop`, showModal's default handler), attributed to `_current_fn_name` (global inits run inside `setup`).
- Only functions from included files go (origin via `line_map`; lambdas are never stripped on their own, a lambda inside a stripped function goes with it). The main file's are kept: the language documents numeric callback ids (`set(on_click, 1)`, used by printer_menu examples), which the analysis can't see.
- Function ids: kept functions keep the first pass's ids (`CodeGen.keep_functions` name → id; lambdas are numbered after the largest kept id), so numeric ids still match; the header now writes `codegen.func_ids` instead of renumbering. The VM looks functions up by id (`find_func`), gaps are fine.
- Widget page: a function whose only other caller was stripped becomes init-only, so more static setup moves to the page (tablet `ui_status_bar`).
- Effect: 134 example builds 198 653 → 180 097 B (-9.3%), mostly lib/sysinfo.fl, tablet ui.fl in the sub-apps (-20 % each), the .fl `flexLayout` under native_flex (flex_demo 1047 → 441 B), lilygo weather http/epd helpers. Every other example's bytecode identical; for the changed ones every kept function has the same id/kind and the same code (calls compared by callee name), apart from the widget-page case above.
